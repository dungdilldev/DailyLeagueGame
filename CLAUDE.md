# Summoner's Quiz

A daily League of Legends "higher or lower"-style quiz. Each day the player gets rounds of 4 champions and must pick the one with the highest value of a stat (win rate, pick rate, skin count, release date, base HP, ...). Static website, no backend. New quizzes are generated automatically.

See [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) for the roadmap and phase status, and [docs/LOCAL_TESTING.md](docs/LOCAL_TESTING.md) for how to run and test locally.

## Tech Stack

- **Frontend:** Vite + TypeScript (strict) + Preact (or vanilla TS if the UI stays small). CSS modules / plain CSS, no heavy UI framework.
- **Data pipeline:** Node.js scripts in TypeScript, run via `tsx`. Runs in GitHub Actions on a cron.
- **Tests:** Vitest (unit, plus Testing Library for the UI flow), Playwright (a few e2e smoke tests, Phase 4).
- **Hosting:** Static hosting (GitHub Pages or Cloudflare Pages). No server, no database. Player state lives in `localStorage`.
- **Lint/format:** ESLint + Prettier. Config is the source of truth, don't argue with it.

## Commands

Keep this list accurate, it is the first thing to check. Node 22+ (see `.nvmrc`).

- `npm run dev` - local dev server
- `npm run build` - typecheck + production build, with the puzzles of today (UTC) and tomorrow built into the game pages; `PUZZLE_DATE=YYYY-MM-DD` builds for another day
- `npm run check` - typecheck + lint + format check + unit tests (run before pushing, plus `test:e2e`)
- `npm test` - unit tests (`npm run test:watch` for watch mode)
- `npm run test:e2e` - Playwright smoke tests against a fresh production build (first time: `npx playwright install chromium`)
- `npm run lint` / `npm run typecheck`
- `npm run format` / `npm run format:check` - Prettier
- `npm run data:refresh` - fetch Data Dragon, update `public/data/champions.json`, `items.json` and `abilities.json` and the icons in `public/images/icons/` (needs network)
- `npm run images:download` - download the esports team, league and player images listed in `data/esportsImages.json`, the region crests in `src/data/crestImages.ts` and the stat symbols in `src/data/statIcons.ts`, skipping files already there (needs network and curl)

## Domain Rules (non-obvious, easy to get wrong)

- **Puzzles are generated at build time and built into the pages, not stored** (owner, 2026-11-05). `createDailyPuzzle(data, date, mode)` builds a day's puzzle from the data files and the question files in `data/questions/`; there are no puzzle files in the repo. Every game page carries **today's and tomorrow's** puzzle (`buildPuzzleDays`, `PUZZLE_DAYS_PER_PAGE`): round 1 of today's as real markup (what a first visit shows and crawlers read; never the answer), and both days as JSON with only what the cards need. The browser picks the day by its UTC date (`pickPuzzleDay`); after midnight it plays tomorrow's, and if a build was missed and the page has neither, it plays the newest with a note. An inline script hides the built-in round 1 when the app will show something else (saved progress, another day), so it never flashes up. The production bundle has no data files, question files, player file or generator; only the dev-only endless mode loads them. Answers are in the page source (tomorrow's a day early): this is a casual game, do not treat them as secret.
- **Daily rebuild:** `deploy.yml` builds and deploys at 12:00 and 22:00 UTC, so either run covers the next midnight; a failed data refresh does not stop it (it builds from the last committed data), failing tests do. After deploying it checks that the live page carries today's puzzle. GitHub turns off scheduled workflows of a public repo after 60 days without activity; the data commits every patch keep it active.
- **Determinism:** the same date + same data snapshot must always produce the same puzzle, for every player. Use the seeded PRNG (seed = date string), never `Math.random()`, and no clock inside generator code.
- **Today only:** only today's puzzle can be played (owner, 2026-11-05; earlier days could be played until then). An old `?date=` link opens today and the parameter is removed. Saves from that time may carry `late: true`; such days still do not count for the streak, and the flag is no longer written.
- **Four data files, four jobs:** `champions.json` has all champion stats, `items.json` all item stats, `abilities.json` all ability stats (all three generated), `data/questions/<category>.json` the question templates (hand-edited, one file per category). A question names one stat (`stat`), so it is about champions, items or abilities depending on which file defines that stat. Optional lists narrow who can appear: `correct` (only these can be the answer), `wrong` (only these can be the other options), `exclude` (never used). An id may be in only one list. Lists are checked against the data on every refresh: an id that no longer exists fails the run. A question is asked at most once a day.
- **Category and difficulty:** every question has both. `category` is `stats`, `lore`, `esports` or `trivia`, and **the file decides it**: a question in `data/questions/lore.json` is a lore question, and an entry that writes its own `category` is rejected. Ids must be unique across all files. Each file keeps its questions in a fixed order: reordering or moving questions between files changes the puzzles (see "Generator changes move old puzzles"). Lore questions are pick questions whose lists are written by hand, checked against the League of Legends Wiki region and event pages (not a pipeline source): check a list there before adding or changing it, and keep out any champion the wiki also ties to another region, so no option can be argued to be right or wrong. The exception is the title question. Esports questions are of three kinds: about esports skins (generated, see esports skin lines); and about the history of the World Championship (teams, players, regions, final cities), as `text` options; and about players and their teams and nicknames, generated from `data/players.json` (see player questions). Those facts come from the Wikipedia results table and go stale: **after every Worlds final (November), re-check the esports lists** (new champion, new finalist, new host city, new T1 players, teams that may now have won; add the year to every `byYear` list: winners, runners-up, Finals MVP, final city, anthem; after MSI the MSI winner, runner-up and final city, and re-check `mostMsiTitles` and `onlyWesternMsiWinner`; add the winner's skin prefix to `pipeline/esportsSkins.ts` once its skins ship; add new titles, transfers and players to `data/players.json`). **A renamed team counts only under its own name** (user, 2026-11-19): in pick lists a result belongs to the name the team had when it happened, so Samsung Galaxy's 2017 title is not Gen.G's and KOO Tigers' 2015 final is not Hanwha Life's (`isWorldsChampion`, `lostWorldsFinal`). Trivia questions are about the game itself and its development (scrapped champions, removed and current game modes, maps, items and summoner spells, voice line easter eggs, champion name origins, music bands, Ultimate skins, Riot's other games, Riot Forge games and Arcane, Summoner's Rift and ranked history, April Fools, Riot Games), all pick questions written by hand from the League of Legends Wiki (Unreleased Content, Magma Chamber, Dominion, Twisted Treeline, Summoner spell, Removed items, Mythic item, Champion update, the champions' Audio and Trivia pages, Featured game mode and each mode's page, Poro, Easter egg, Cho'Gath Eats the World, Astro Teemo, Dragon pit, Riot Forge, Song of Nunu, Arcane, VALORANT, Rank, Riot Games) plus Data Dragon skin names for the band members and the release order in `champions.json` for the 100th champion; every question has a `subcategory` (one per topic: `unreleased-champions`, `cancelled-features`, `removed-modes`, `game-modes` (modes and maps still in the game; both extended 2026-11-24 from the wiki page Featured game mode, which sorts modes into current and retired: re-check when a mode is retired or a new one ships, and a wrong mode never shares the asked trait, e.g. no Odyssey or Invasion in the first limited champion pool question), `removed-summoner-spells`, `removed-items`, `original-champions`, `champion-updates`, `real-life-changes` (champions changed for a real-world reason: censorship, a sound like an air raid siren, a throne like a cross; written 2026-11-24 from the champions' Trivia and Cosmetics pages and the V6.7 and V6.8 patch pages; a wrong option must not appear in the V6.7/V6.8 Global Splash Unification lists, whose changes often give no reason), `champion-kits` (firsts and onlies in champion abilities), `champion-trivia` (one champion's oddity or "only champion who…" fact, from the champions' Trivia pages), `dances` (what a champion's dance references, and dance easter eggs; written 2026-11-22 from the Trivia section of each champion's `<Champion>/LoL` wiki page, current dances only: a reference the wiki lists under an older version of the champion is not used, and a champion who shares the dance, or once did, is never a wrong option; re-check after a rework or a new champion), `voice-lines`, `nemesis-quests` (who each champion's Nemesis Quest is against, how it is won, and the quests that were only on the Bridge of Progress; written 2026-11-24 from the wiki page Nemesis Quest: re-check it when a quest is added or removed), `client-minigames` (the limited-time minigames in the client: who starred in them, what kind of game each was, codenames; written 2026-11-24 from the wiki category Client minigames and each minigame page, verbatim facts only. A wrong champion is never one the page names (starring or mentioned) nor one with a skin of the event's line (Soul Fighter, Star Guardian, Spirit Blossom), and a wrong minigame never shares the genre (The Battle of Koeshin is also listed as a card game, Koeshin's Courtyard succeeds Spirit Bonds). Rise of the Sentinels is left out because it would answer the lore Sentinels of Light questions. Add a new minigame when one ships), `voice-actors` (which champion an actor voices in English, and which champion shares an actor with another; written 2026-11-24 from the wiki page Voice cast (League of Legends)/en, current base voices only. A wrong option is never a champion the actor voices anywhere on that page, skins and pre-update voices included, nor one sharing any actor with the named champion; champions whose credit is speculation, unaccredited or artificial (Miss Fortune, Anivia, Bard, Rek'Sai, Aphelios) are not used. Re-check after a champion update with a new voice), `easter-eggs` (champion interactions, cosmetic buffs, shop search terms, map changes, release teasers and removed easter eggs; written 2026-11-24 from the wiki's Easter egg page, whose small +1 bonuses and teasers change without notice: re-check it when a champion is reworked), `names-and-references`, `music-bands`, `ultimate-skins`, `skin-history`, `spin-offs`, `summoners-rift`, `ranked-history`, `april-fools`, `riot-games`), so a day asks one question per topic. **A wrong option must be something the source does not tie to the answer**, and dated facts (removed items, monsters and tiers "added in" a year, Ultimate skins, bands) can go stale: re-check them when a new band, Ultimate skin, monster or tier ships. So can "the only champion who..." questions (`champion-kits`, Rammus's voice lines): re-check them when a champion is released or reworked. `difficulty` is `easy`, `medium`, `hard` or `variable`: the 5 rounds accept easy; easy or medium; medium; medium or hard; hard (`ROUND_TIERS` in `generate/config.ts`; user, 2026-11-20: with one medium round, a medium question came up a quarter as often as an easy one), a fixed difficulty only appears in rounds that accept it, `variable` in any round. Stat questions are all `variable` because their difficulty comes from the round's gap band, and so are the generated player questions (user, 2026-11-19), whose difficulty depends on the player or team drawn; this also gives the esports easy rounds more than the few easy questions to choose from.
- **Answer text:** any question, of any kind and category, may have an optional `answer`: a short text shown under "Correct!" / "Not quite" once the player has picked (`Round.explanation`, added in one place, `buildRound`, so every kind of question gets it; it does not touch the random draws, so it never moves a puzzle). **It must be true for every option that can be the answer**: a question with several `correct` entries, or a generated one (player, year, clue, logo, skin line), picks a different answer on different days, so its text may not name one of them. A pick question may instead give one text per right option (`answerFor`, keyed by option id, only ids from `correct`): the day's answer gets its own text, any other right option falls back to `answer`. Such a text may name its own option, since it is shown only when that option is the answer (e.g. `abilityNamedLikeTitle` names each champion's ability and title; the clue question cannot quote that title the same day, because a champion appears at most once a day). Write it from the same source as the question (lore: the LoL Wiki page), one or two sentences that add something the question did not say; no filler. **It must not answer another question that can come up the same day**: a question of another slot (category and subcategory) whose answer the text names together with that question's premise (e.g. "the First Lands, now Ionia" answers the Titan War question; naming a place next to its nation answers "which of these places is in X?"). Texts within one slot may overlap, since a slot is asked once a day. That is also why most esports history questions have no text: their facts are each other's answers. Written 2026-11-04 from the wiki pages the questions come from; most lore and trivia questions have one, stat and generated questions none.
- **Subcategory:** an optional `subcategory` (lowercase words joined by hyphens, e.g. `geography`, `return-of-the-ruined-king`) on any question groups related questions inside a category. All questions of one category and subcategory share **one slot in the daily puzzle**: slots are tried in a random order weighted by the square root of their size (`SLOT_SIZE_WEIGHT_EXPONENT`; user, 2026-11-20: with equal weights a lone question came up every few days and one of the 36 `nations` questions once in two years), and a day asks at most one question of a subcategory (`orderBySlot` in `generate/buildPuzzle.ts`). **In the mixed mode the categories take turns** (user, 2026-11-19): each offers its slots in that weighted order, so every category gets about a quarter of the rounds however many slots it has (stats has 29, esports 5). The testing mode also gets a Subcategory dropdown and groups its question list and coverage table by it. **Every esports and lore question has one** (user, 2026-11-19); a question without a clear topic goes into `trivia`. Stat questions have none, so each stat is its own slot. Esports subcategories: `worlds` (every World Championship question: teams, players, finals, anthems), `msi`, `moments`, `players` (the generated player questions) and `trivia` (skin line, logo, trophy, leagues, Hide on bush, First Stand), so an esports day asks one question of each. Esports has exactly as many slots as rounds, so every slot is asked every day: **each slot needs questions of every difficulty** (or `variable` ones), or its only easy or medium question fills that slot's rounds of that tier day after day. Lore subcategories: `champion-origins` (which champion belongs to a region), `races` (yordle, Void, Darkin, Ascended, Iceborn), `trivia` (the title clue, Tellstones), `geography` (continents, seas, islands, deserts, mountains), `nations`, `city-states` and one per event of the wiki timeline (`titan-war`, `war-of-the-three-sisters`, `rebellion-of-icathia`, `great-darkin-war`, `reign-of-the-iron-revenant`, `ruination-of-helia`, `rune-wars`, `first-demacian-noxian-war`, `noxian-invasion-of-ionia`, `avarosan-winters-claw-rift`, `medardan-succession-war`, `era-of-hextech`, `establishment-of-the-trifarix`, `rebirth-of-the-sun-disc`, `rescue-of-the-demacian-prince`, `fall-of-the-reaver-king`, `return-of-the-ruined-king`, `great-mage-rebellion`), plus four from the wiki's Category:Lore concepts (written 2026-11-24): `magic` (forms of magic and their users, World Runes; Universe:Magic, whose "Notable Users" lists decide right and wrong options), `materials` (True Ice, petricite, relic stones), `technology` (hextech, chemtech, shimmer; the Hextech and Shimmer pages carry a "canonical inconsistencies" banner, so re-check them after an Arcane or Zaun story) and `artifacts` (named weapons and relics and who wields them; Universe:Unique items). These were written from the League of Legends Wiki pages Universe:Runeterra, Universe:Timeline and each location, event and concept page; **a wrong option must be a champion or place the wiki does not tie to the event, location or concept**, so check the page before adding one. A text option that answers another slot's question must not appear in an answer text either (`geoPetriciteForest` already says what petricite is made of, `isSentinelOfLight` who made the relic weapons, so neither is asked again). Nothing in the data checks that, only the spelling of ids.
- **Game modes** (`src/game/gameMode.ts`): the player chooses `mixed` (every question; the original puzzle, unchanged) or one category (`stats`, `lore`, `esports`, `trivia`) on the static start page (`index.html`: headline, countdown and one short card per mode; the longer explanations live in `how-to-play.html`) or with the links at the top of the game. Modes are shown, and suggested after a finished day, in the order of `GAME_MODES` (trivia, lore, stats, esports, mixed; owner, 2026-11-04), which is written out on its own: the order of `QuestionCategorySchema` decides how the question files are combined, so changing it would move every mixed puzzle. **Each mode is its own page, named after the mode** (`lore.html`; `modePageHref` in `src/ui/modePages.ts`), with its own title, description and heading, so search engines see five pages with content instead of one empty one; switching mode is a page load. A new mode needs a new page (and an entry in `PAGES`, `public/sitemap.xml` and the redirect list in `play.html`). Old links are redirected by inline scripts: `/` with game parameters (`?category=`, `?date=`, `?mode=`, `?seed=`) goes to `play.html`, which sends `?category=X` to `X.html` (no category: `trivia.html`, `DEFAULT_GAME_MODE`, which is also where the start page button and the header and footer "Play" links go; an unknown or hidden category: the start page, without the parameters, or it would send the link back to `play.html`; owner, 2026-11-22) and keeps the other parameters. A category plays only its questions, with its own seed (`date:category`), its own saved progress (`dailyleague:v1:<category>`; mixed keeps `dailyleague:v1`) and its own streak and share text. A pool with fewer questions than rounds gives a shorter day (no category is that small at the moment); a pool with nothing left that fits a round's tier takes the nearest tier instead. The endless mode ignores modes. **Esports is hidden for now** (owner, 2026-11-22: its questions do not work well yet): `HIDDEN_CATEGORIES` in `gameMode.ts` takes it out of `GAME_MODES` (mode links, suggestions) and out of the mixed puzzle; **the live site must offer no way to reach it**, so there is no `esports.html` (deleted, not in `PAGES`: the address is a 404, and with no page there is nowhere for an ad; `e2e/smoke.spec.ts` and `e2e/ads.spec.ts` check this), no start page card, sitemap entry or `play.html` mode, and the how-to-play, about and mixed pages do not mention it. `?category=esports` is an unknown category like any other and opens the start page. Its questions, generators, images and tests stay, and the dev-only endless mode still asks them. To bring it back: empty `HIDDEN_CATEGORIES`, restore `esports.html` and its `PAGES` entry, the start page card (and the 5-column grid in `landing.css`), the sitemap entry, the `play.html` list and those texts from git history (the commit that added `HIDDEN_CATEGORIES`), and drop the two 404 tests.
- **Clue questions** (`clue: "title"`, e.g. `Which champion is known as "{title}"?`) are made from the champion data: a random champion's epithet from Data Dragon is quoted, that champion is the answer and three random others are the options. They need no lists, only `subject: champion`, `label`, `question` with the `{title}` placeholder and optionally `exclude`; they fit every difficulty gap like a pick question.
- **Pick questions** have no stat (`{ id, subject, label, question, correct, wrong, exclude? }`, e.g. "Which of these champions is a yordle?"). Both lists are written out in full: one option comes from `correct`, three from `wrong` (so at least 3). `subject` is required because there is no stat to tell champions from items; it is `champion`, `item` or `text`. `text` options (team names, players, cities) have no data file and no icon: the lists hold the names shown on the cards, the name is the id, they are never checked against the data, and they are used at most once a day like everything else. Difficulty bands do not apply (there are no values), so they can land in any round; the round shows no values after answering. Unknown fields are rejected, so a typo in a key fails loudly.
- **Players file:** `data/players.json` is hand-written (not a pipeline source): the first 15 players from their Wikipedia articles, the other 87 from web search summaries (Leaguepedia, Liquipedia, news). **`titles` and `teams` of all 102 were checked against Leaguepedia on 2026-11-19** (Cargo tables `TournamentPlayers` for every Worlds and MSI winning roster and each player's rosters, `Tenures`, `TeamRenames`; a coaching stint is not a team). `nickname`, `region` and `role` are still unverified. It goes stale: **after every Worlds and MSI, add new titles and transfers**. `titles` holds only Worlds and MSI. A team counts under the name it had when the player was there, with these exceptions, which the file already used: SK Telecom T1 is "T1", Afreeca / Kwangdong / DN Freecs are "DN SOOPers", Damwon / DWG KIA are "Dplus KIA", Longzhu / Kingzone DragonX are also "DRX", ROX Tigers is "Hanwha Life Esports", and a sponsor prefix is dropped (Kiwoom DRX is "DRX", HANJIN BRION is "OKSavingsBank BRION"). So Ucal's ThunderTalk Gaming years are not "Dominus Esports". It is bundled into the app. **The `teams` lists must be complete for the pro teams that matter, and `titles` must be complete:** a player question treats every team or title missing from a list as a wrong option, so an omission can make a wrong option right. `role` (required: `top`, `jungle`, `mid`, `bot`, `support`) is the role of the player's best-known stretch, filled in from general knowledge on 2026-10-24 and unverified like the rest; players known in two roles (Perkz, CoreJJ, Xiaohu, Rekkles, Zven) are excluded from the role question.
- **Player questions** (`ask`, `subject: text`) are made from `data/players.json`; they need no lists, only `label` and `question`, optionally `exclude`, and like pick questions show no values. Kinds: `playerByTeam` (`{team}`: a player who played there vs players who did not), `teamByPlayer` (`{player}`: one of their teams vs teams they never played for), `playerByNickname` (`{nickname}`), `playerByRole` (`{role}`, written as "top laner", "jungler", "mid laner", "bot laner", "support"), `playerByRegion` (`{region}`: a player of that region; a wrong option is from another region **and never played for any team that a player of that region played for**, because e.g. Viper (Korea) made his name in China too), `playerWithTitle` / `playerWithoutTitle` with `event: "Worlds" | "MSI"` (has won it vs has never won it), and `playerWithTitleInYear` (`{year}`: won the `event` that year; wrong options include winners of other years, so every winning roster must be complete in `titles`). `event` is required for these three and rejected elsewhere. A player listed only as a substitute on a winning roster (Bengi at MSI 2016) is arguable either way and goes into the question's `exclude`.
- **Memorable moments** (`subcategory: "moments"`, esports pick questions, one slot a day): each moment is asked in the format that fits it (who: player names; which team: team names, which show logos when all four have one; which champion: champion icons; which year: years as text). Every fact was checked on Wikipedia, Leaguepedia or a sourced esports article on 2026-10-24. **A wrong option must have nothing to do with the moment**: no other player or team from that series, and for champion questions the wrong options are champions **released after the moment**, so none of them can have been played in that game. Text questions must start with "Which" (a test checks the wording). A new moment's question must not state a fact that a `byYear` list asks for (e.g. "DRX won in 2022"), because another round the same day could ask it.
- **Esports skin lines** (`skinLine: "esports"`, `subject: champion`, `{line}` placeholder, `buildSkinLineRound`): `pipeline/esportsSkins.ts` reads each champion's esports lines from the start of Data Dragon's skin names (team prefixes such as SSG, iG, DRX, and the yearly "Worlds 2019" skin) into the optional `esportsSkinLines` champion field. The answer has a skin in the named line, the wrong options have none. **SKT T1 and T1 are one line, "T1 or SKT T1"**, so a champion with an SKT T1 skin is never offered as having no T1 skin. A new Worlds winner's skin prefix must be added to `TEAM_PREFIXES`, or that line is missing (not wrong). The refresh fails if fewer than 40 champions have a line.
- **Logo question** (`logo: "team"`, `subject: text`, `buildLogoRound`): the round shows one team's downloaded logo above the question (`Round.clue: "teamLogo"`, `clueImageUrl`) and offers that team and three others as plain names. **A round with a clue never shows option images** (`roundSymbols`), or the cards would answer it. Its `teams` list is curated by hand: well-known teams only, one logo per organisation (no T1 next to SK Telecom T1, no Damwon next to Dplus KIA, one Samsung team), and no near-black logos that vanish on the dark background; a test checks each has an entry in `data/esportsImages.json`. Check a logo by eye before adding a team.
- **Region and group crests** (`src/game/textSymbols.ts`, list in `src/data/crestImages.ts`): text options named exactly like a region or group (Demacia, Shadow Isles, The Black Rose, House Medarda...) show the crest from the LoL Wiki image host (user-approved third-party source), downloaded by `npm run images:download` into `public/images/crests/` (the wiki's own PNG or SVG, named after the wiki file) and served by the app. A round shows crests only if **all four** options have one, otherwise the plain cards would hint at the answer. Never map a place inside a nation to that nation's crest (it would reveal "which of these places is in Demacia?"). To add a symbol, add the option name and the wiki file name (`<Name> Crest icon.png`) to `CREST_FILES` and run the download; a test fails if a crest has no file.
- **Esports images** (`data/esportsImages.json`, validated by `src/data/esportsImages.ts`): maps `teams`, `leagues` and `players` to file names on Leaguepedia (user-approved source). `npm run images:download` (`pipeline/downloadImages.ts`, shells out to curl because Fandom blocks Node's HTTP client; skips files that already exist, so delete one to fetch it again) saves each as a 160px WebP in `public/images/esports/<kind>/<slug>.webp`, which is committed and served by the app; nothing is hotlinked at runtime. Teams are logos (`<Team>logo square.png`); players are the player page's main photo, resolved once and **not hand-checked** (a few show an old in-game name or an old team). A new team or player needs an entry plus a download run to get an image, and logos are not refreshed automatically after a rebrand. The all-or-nothing rule applies, and a round never mixes logos and photos. Photos are not shown for `playerByTeam`, because the jersey would answer it (`QUESTIONS_WITHOUT_PHOTOS`). A test fails if an entry has no downloaded file.
- **Questions about a given year** (`byYear` list, `subject: text`, `{year}` placeholder, `buildYearRound`) carry their own data: one `{ year, answer }` per year, written in `data/questions/esports.json`. A round names a random year, the answer is that year's entry and the wrong options are answers of other years (so at least 4 different answers, and each year once; an answer may repeat across years). Used for Worlds and MSI winners, runners-up and final cities, Worlds Finals MVPs (2014 on: sources disagree before that) and Worlds anthems (2014 on). The MSI questions share the `msi` subcategory and the Worlds ones `worlds`, so a day asks at most one of each. **One name per organisation within a list**, or a wrong option could be argued to be the same team: T1 for SK Telecom T1, Royal Club for Star Horn Royal Club; otherwise era names (Samsung White, Damwon Gaming, DWG KIA). Checked against the Wikipedia Worlds results table and finals pages. Like the other Worlds facts they go stale: **after every Worlds final and MSI, add the new year to each list** (MSI 2020 was cancelled).
- **Snapshots:** each data file holds its own snapshot in effect plus any upcoming one; a day uses the snapshot of each file in effect on that day. New or changed data becomes a snapshot with `effectiveFrom` = next UTC day, so a day's puzzle never changes once that day has started. The build picks, for each day it builds, the newest snapshot with `effectiveFrom <=` that day. Never edit a snapshot that is already in effect. "Changed" ignores key order (Zod reorders keys on parse), and a snapshot identical to the one before it is dropped, so unchanged data never adds a copy.
- **Date handling:** the "day" is defined in **UTC**. Never use local time to pick the puzzle.
- **Fair, escalating rounds:** all 4 champions in a round have distinct values. The relative gap between first and second place must fall in the round's band from `pipeline/generate/config.ts`; bands narrow each round so later rounds are harder. Win rate / pick rate comparisons (Phase 5) should stay within the same role and patch.
- **Data sources:** Data Dragon (official) and the LoL Wiki: champion data (release dates), item data and gold value table (Lua modules, parsed by `luaTable.ts`), each champion's "Patch history" page and each ability's data template (both via a few batched API calls, `leagueWikiPages.ts`). Each lives in one file under `pipeline/sources/`. A stat may return `undefined` for an entity (e.g. not on the wiki yet); validation requires 95% coverage per stat (a stat can lower that) and at least 8 values.
- **Champions, items and abilities:** every stat has a `subject`. A round compares four champions, four items or four abilities, never a mix, and nothing appears twice in a day. Item pool: completed legendary items and boots sold on Summoner's Rift (`items/selectItems.ts`). Item gold efficiency counts the item's stats only (wiki gold values), not passives, and is left out for an item with a stat of unknown value instead of guessing. "Patch changes per year" counts patch-history entries, which include bug fixes and hotfixes, so its question says "patch changes", not "balance changes". "Per year" stats (`pipeline/stats/perYear.ts`) divide by the champion's age measured up to the **newest champion's release date in the data, never today**: a clock would change every value daily and create a data snapshot daily. Champions younger than a year count as one year old.
- **Abilities** (`abilities.json`, ids like `AhriQ`, shown as "Ahri Q · Orb of Deception" with Data Dragon's spell icon): the numbers come from each ability's wiki data template (`Template:Data <Champion>/<Q|W|E|R>`), never from Data Dragon, whose spell numbers are stale. Every value is **at max rank** (rank 5, ultimates rank 3, Jayce/Udyr style champions their own top rank) and every ability question says so. Only values that cannot be argued are kept: damage and ratios only for an ability with exactly one champion damage line (minion, monster and reduced-damage lines are ignored; per-tick, total-plus-per-hit, minimum/maximum and "bonus" lines leave the ability out), and any ratio part that is a formula (e.g. `% per 100 AP`) drops the whole line; cooldown is left out for abilities with charges (`recharge`); mana cost only when the cost is mana alone. Damage and cooldown are split into basic abilities and ultimates; AP, bonus AD and total AD ratios are separate stats because they do not compare. An ability is left out when the wiki's ability name is not Data Dragon's name for that slot (or one of its forms), so an icon never shows another ability's numbers. There is no health-ratio stat: only one damage line scales with the champion's own health.
- **Endless mode** (`?mode=endless[&seed=...]`, `src/game/endless.ts`, `EndlessScreen`) is a testing tool that only exists in development builds (`npm run dev`; in production `?mode=endless` shows the normal game and the code is not in the bundle, gated by `import.meta.env.DEV` in `main.tsx`, which loads `EndlessApp` and the data with a dynamic import). It gives random questions, uniform over stats, an optional category (the question list then shows only that category), forced question/difficulty, and a coverage table grouped by category. It is seeded, saves nothing and never touches the streak. Keep it working when adding stats; its tests check that every stat and difficulty appears, and its Playwright tests run against the dev server.
- **Generator changes move old puzzles:** the puzzle is generated from date + data + stat list + generator code. Adding stats or changing the generator changes the puzzle for every date, including today, from the next deploy on. Saved answers that no longer fit are dropped automatically.
- **Stat provenance:** each stat definition carries its `source`, published in its data file. Stat definitions (label, format, symbol) and questions are data too: the client has no stat-specific code. A stat may name its in-game symbol (`unitIcon`, one of `src/data/statIcons.ts`: the LoL Wiki files, downloaded by `images:download` into `public/images/stats/`), published as `unitIconUrl` and drawn after each value like a unit; stats the game has no symbol for (skins, dates, patch changes, gold efficiency) and base damage (physical or magic, so no single symbol fits) have none. A test fails if a symbol has no file. A stat may also write a text `unit` after each value ("skins per year") and name `details`: other stats of the same file shown under each option's value once answered (skins per year shows the skin count and release date, patch changes per year the patch-change count, `patchCount`, and release date); a detail is left out of a round when one of its options lacks it, and it never touches the random draws.
- **No official win-rate API exists** (popularity stats are parked, see plan Phase 5b). Riot does not expose aggregate champion win/pick rate. Whatever source is used must be isolated behind the `pipeline/sources` interface so it can be swapped (see the plan, Risks).
- **Ads only on the game pages** (owner, 2026-11-03): the mode pages (`stats.html`, `lore.html`, ...) are the only pages that may show ads (`src/ui/AdSlot.tsx`; never in the endless mode). **The one banner (owner, 2026-11-09) is a 160x600 skyscraper in the empty margin left of the game on windows at least `AD_RAIL_MIN_VIEWPORT_PX` (1280px, also in the `.ad-slot` media queries in `ui/game.css`) wide, and a banner below the game and the support link on narrower ones (phones, tablets)**; one responsive AdSense unit, sized by the CSS of its placement (`ad-slot--rail` / `ad-slot--below`). The placement is chosen once, when the banner first shows, because a loaded ad keeps its size; resizing across the width afterwards hides it. It never covers, sits between or moves the cards. The start page and the info pages never load ad code: an ESLint rule forbids importing `src/ads` or `AdSlot` from `src/pages`, and `e2e/ads.spec.ts` checks that those pages never request Google's ad script. Ads are off unless a build sets `VITE_ADS_ENABLED=true` and `VITE_AD_SLOT_ID`, and load only after consent (IAB TCF) where it is required; Google's consent message is loaded on its own first (`src/ads/googleConsent.ts`), because the ad script that would otherwise bring it may not load before consent. Keep ad slots away from the answer cards and the Next button. Do not put the AdSense script in any page's HTML: it would load on every page (and with Auto ads, place ads there) before consent.
- **Riot legal:** include the required "not endorsed by Riot Games" disclaimer in the footer. Do not host Riot assets beyond what Data Dragon / Community Dragon terms allow. **Every image is served from our own host** (owner, 2026-11-05): champion, item and ability icons are fetched from Data Dragon by `data:refresh` (`pipeline/icons/`) into `public/images/icons/<champions|items|abilities>/<id>.png` (named after our id; all of them again when the Data Dragon version in `version.txt` changes, otherwise only missing ones; icons no snapshot uses are deleted), and the data files hold those paths (snapshots from before 2026-11-05 still name Data Dragon). Nothing is hotlinked at runtime; `e2e/images.spec.ts` fails on any image from another host.

## Maintainability & Clean Code

These are requirements, not suggestions. Apply them to every change.

**Structure**

- Keep **game logic pure**: functions take data and return data. No DOM, network, clock, or randomness inside them (inject those as parameters). This is what makes it testable.
- **Separate concerns by layer:** `pipeline` (produces data) -> `data` (loads/validates) -> `game` (rules) -> `ui` (renders). Dependencies only point in that direction. `ui` must not import from `pipeline`.
- One module = one responsibility. If a file needs "and" to describe it, split it. Aim for files under ~200 lines and functions under ~30.
- **Adding a new stat must be one new file** in `pipeline/stats/` plus registration in one list. If it requires touching the UI or generator, the abstraction is wrong, fix the abstraction.

**Code style**

- TypeScript `strict`. No `any`; use `unknown` and narrow. No non-null `!` assertions without a comment explaining why.
- Names describe intent (`pickHighestChampion`, not `process`). No abbreviations except domain-standard ones (`wr` is not one, write `winRate`).
- Prefer small pure functions, early returns, and immutable data. Avoid deep nesting (max 3 levels).
- No magic numbers or strings: put them in named constants or config (e.g. `MIN_STAT_GAP`, `ROUNDS_PER_DAY`).
- Don't duplicate. Third repetition means extract; but don't abstract on the first use.
- Comments explain **why**, not what. Delete commented-out code. No TODOs without an issue or plan reference.

**Data & errors**

- Validate all external data at the boundary (Zod or equivalent). Everything past the boundary is typed and trusted.
- **The browser loads no Zod** (user, 2026-11-19): it was three quarters of the JavaScript of every page. Browser code imports only types from the schema modules (`data/schema.ts`, `playerSchema.ts`, `esportsImageSchema.ts`, `questionFiles.ts`); plain values live in Zod-free modules (`questionCategory.ts`, `esportsImages.ts`), bundled files are checked by the tests instead, and `localStorage` is checked by hand (`progressStore.ts`). The dev-only endless mode may use Zod (dynamic import). `e2e/bundle.spec.ts` fails if a page's scripts contain it.
- The pipeline must **fail loudly**: if a source returns bad/partial data, the CI run fails and the previous good data stays live. Never publish a puzzle built from invalid data.
- The client must degrade gracefully: if today's puzzle file is missing, show a clear message (or fall back to the latest available puzzle), never a blank page.

**Testing**

- Every function in `src/game` (including the generator) and `pipeline` has unit tests, including edge cases (ties, missing stat, patch change, date boundary at UTC midnight).
- Add a regression test with every bug fix.
- Generator has a property-style test: for N seeds, every produced round is valid (4 distinct champions, unique max, gap respected).
- Don't mock what you own. Mock only network and clock.

**Dependencies**

- Be sceptical of new dependencies. Prefer the platform and the standard library. Pin versions; justify each addition in the PR/commit message.

**Workflow**

- Small, focused commits with imperative messages ("Add skin count stat"). One concern per commit.
- Keep `IMPLEMENTATION_PLAN.md` current: tick off tasks as done, record decisions that change the plan.
- Update this file when a convention changes. Stale docs are bugs.
- Before finishing a task: typecheck, lint, tests pass; no unused code or exports left behind.
