# Summoner's Quiz

A daily League of Legends "higher or lower"-style quiz. Each day the player gets rounds of 4 champions and must pick the one with the highest value of a stat (win rate, pick rate, skin count, release date, base HP, ...). Static website, no backend. New quizzes are generated automatically.

See [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) for the roadmap and phase status, and [docs/LOCAL_TESTING.md](docs/LOCAL_TESTING.md) for how to run and test locally.

## Tech Stack

- **Frontend:** Vite + TypeScript (strict) + Preact (or vanilla TS if the UI stays small). CSS modules / plain CSS, no heavy UI framework.
- **Data pipeline:** Node.js scripts in TypeScript, run via `tsx`. Runs in GitHub Actions on a cron.
- **Tests:** Vitest (unit, plus Testing Library for the UI flow), Playwright (a few e2e smoke tests, Phase 4).
- **Hosting:** Static hosting (GitHub Pages or Cloudflare Pages). No server, no database. Player state lives in `localStorage`.
- **Lint/format:** ESLint + Prettier. Config is the source of truth, don't argue with it.

```
  sources/     One module per external data source (Data Dragon, LoL Wiki champions / items / patch history / ability templates, batched wiki page fetch, luaTable parser).

  items/       Which items are asked about (selectItems) and their gold efficiency.

  data/        Generated output, committed by CI: champions.json (champion stats + snapshots), items.json (item stats + snapshots) and abilities.json (ability stats + snapshots).

```

## Domain Rules (non-obvious, easy to get wrong)

- **Puzzles are generated in the browser, not stored.** `createDailyPuzzle(data, date)` builds the day's puzzle from the data files and the question files in `data/questions/`; there are no puzzle files. Answers are therefore inspectable by anyone: this is a casual game, do not treat them as secret.
- **Determinism:** the same date + same data snapshot must always produce the same puzzle, for every player. Use the seeded PRNG (seed = date string), never `Math.random()`, and no clock inside generator code.
- **Archive:** players can open today and the previous `ARCHIVE_DAYS` (7) days via `?date=YYYY-MM-DD` or the day buttons; anything else falls back to today. Days played after their own date are saved with `late: true` and do not count for the streak. Snapshots are kept long enough to rebuild every archive day exactly as it was.
- **Four data files, four jobs:** `champions.json` has all champion stats, `items.json` all item stats, `abilities.json` all ability stats (all three generated), `data/questions/<category>.json` the question templates (hand-edited, one file per category). A question names one stat (`stat`), so it is about champions, items or abilities depending on which file defines that stat. Optional lists narrow who can appear: `correct` (only these can be the answer), `wrong` (only these can be the other options), `exclude` (never used). An id may be in only one list. Lists are checked against the data on every refresh: an id that no longer exists fails the run. A question is asked at most once a day.
- **Category and difficulty:** every question has both. `category` is `stats`, `lore`, `esports` or `trivia`, and **the file decides it**: a question in `data/questions/lore.json` is a lore question, and an entry that writes its own `category` is rejected. Ids must be unique across all files. Each file keeps its questions in a fixed order: reordering or moving questions between files changes the puzzles (see "Generator changes move old puzzles"). Lore questions are pick questions whose lists are written by hand, checked against the League of Legends Wiki region and event pages (not a pipeline source): check a list there before adding or changing it, and keep out any champion the wiki also ties to another region, so no option can be argued to be right or wrong. The exception is the title question. Esports questions are of three kinds: about esports skins (generated, see esports skin lines); and about the history of the World Championship (teams, players, regions, final cities), as `text` options; and about players and their teams and nicknames, generated from `data/players.json` (see player questions). Those facts come from the Wikipedia results table and go stale: **after every Worlds final (November), re-check the esports lists** (new champion, new finalist, new host city, new T1 players, teams that may now have won; add the year to every `byYear` list: winners, runners-up, Finals MVP, final city; add the winner's skin prefix to `pipeline/esportsSkins.ts` once its skins ship; add new titles, transfers and players to `data/players.json`). Trivia questions are about the game itself and its development (scrapped champions, removed maps, items and summoner spells, voice line easter eggs, music bands, Ultimate skins, Riot Forge games and Arcane, Summoner's Rift and ranked history, April Fools, Riot Games), all pick questions written by hand from the League of Legends Wiki (Unreleased Content, Magma Chamber, Dominion, Twisted Treeline, Summoner spell, Removed items, Champion update, the champions' Audio pages, Riot Forge, Arcane, Rank, Riot Games) plus Data Dragon skin names for the band members; every question has a `subcategory` (one per topic: `unreleased-champions`, `cancelled-features`, `removed-modes`, `removed-summoner-spells`, `removed-items`, `original-champions`, `champion-updates`, `voice-lines`, `names-and-references`, `music-bands`, `ultimate-skins`, `spin-offs`, `summoners-rift`, `ranked-history`, `april-fools`, `riot-games`), so a day asks one question per topic. **A wrong option must be something the source does not tie to the answer**, and dated facts (removed items, monsters and tiers "added in" a year, Ultimate skins, bands) can go stale: re-check them when a new band, Ultimate skin, monster or tier ships. `difficulty` is `easy`, `medium`, `hard` or `variable`: the 5 rounds are tiered easy, easy, medium, hard, hard (`ROUND_TIERS` in `generate/config.ts`), a fixed difficulty only appears in rounds of its tier, `variable` in any round. Stat questions are all `variable` because their difficulty comes from the round's gap band.
- **Subcategory:** an optional `subcategory` (lowercase words joined by hyphens, e.g. `geography`, `return-of-the-ruined-king`) on any question groups related questions inside a category. All questions of one category and subcategory share **one slot in the daily puzzle**: slots are tried in random order, a day asks at most one question of a subcategory, and a big subcategory comes up about as often as a single question instead of in proportion to its size (`orderBySlot` in `generate/buildPuzzle.ts`). The testing mode also gets a Subcategory dropdown and groups its question list and coverage table by it. Lore subcategories: `geography` (continents, seas, islands, deserts, mountains), `nations`, `city-states` and one per event of the wiki timeline (`titan-war`, `war-of-the-three-sisters`, `rebellion-of-icathia`, `great-darkin-war`, `reign-of-the-iron-revenant`, `ruination-of-helia`, `rune-wars`, `first-demacian-noxian-war`, `noxian-invasion-of-ionia`, `avarosan-winters-claw-rift`, `medardan-succession-war`, `era-of-hextech`, `establishment-of-the-trifarix`, `rebirth-of-the-sun-disc`, `rescue-of-the-demacian-prince`, `fall-of-the-reaver-king`, `return-of-the-ruined-king`, `great-mage-rebellion`). These were written from the League of Legends Wiki pages Universe:Runeterra, Universe:Timeline and each location and event page; **a wrong option must be a champion or place the wiki does not tie to the event or location**, so check the page before adding one. Nothing in the data checks that, only the spelling of ids.
- **Game modes** (`src/game/gameMode.ts`): the player chooses `mixed` (every question; the original puzzle, unchanged) or one category (`stats`, `lore`, `esports`, `trivia`) on the static start page (`index.html`: headline, countdown and one short card per mode; the longer explanations live in `how-to-play.html`) or with buttons at the top of the game (`play.html`), in the address as `?category=`. Old game links on `/` (`?category=`, `?date=`, `?mode=`, `?seed=`) are redirected to `play.html` by an inline script in `index.html`. `play.html` without a mode plays `stats` (`DEFAULT_GAME_MODE`), whose address has no `?category=`; every other mode, `mixed` too, is named in the address. A category plays only its questions, with its own seed (`date:category`), its own saved progress (`dailyleague:v1:<category>`; mixed keeps `dailyleague:v1`) and its own streak and share text. A pool with fewer questions than rounds gives a shorter day (no category is that small at the moment); a pool with nothing left that fits a round's tier takes the nearest tier instead. The endless mode ignores modes.
- **Clue questions** (`clue: "title"`, e.g. `Which champion is known as "{title}"?`) are made from the champion data: a random champion's epithet from Data Dragon is quoted, that champion is the answer and three random others are the options. They need no lists, only `subject: champion`, `label`, `question` with the `{title}` placeholder and optionally `exclude`; they fit every difficulty gap like a pick question.
- **Pick questions** have no stat (`{ id, subject, label, question, correct, wrong, exclude? }`, e.g. "Which of these champions is a yordle?"). Both lists are written out in full: one option comes from `correct`, three from `wrong` (so at least 3). `subject` is required because there is no stat to tell champions from items; it is `champion`, `item` or `text`. `text` options (team names, players, cities) have no data file and no icon: the lists hold the names shown on the cards, the name is the id, they are never checked against the data, and they are used at most once a day like everything else. Difficulty bands do not apply (there are no values), so they can land in any round; the round shows no values after answering. Unknown fields are rejected, so a typo in a key fails loudly.
- **Players file:** `data/players.json` is hand-written (not a pipeline source): the first 15 players from their Wikipedia articles, the other 87 from web search summaries (Leaguepedia, Liquipedia, news) and **not yet checked against a primary source**, so treat them as unverified and goes stale: **after every Worlds and MSI, add new titles and transfers**. `titles` holds only Worlds and MSI; a renamed organisation appears under its current name (SK Telecom T1 is "T1"). It is bundled into the app. **The `teams` lists must be complete for the pro teams that matter, and `titles` must be complete:** a player question treats every team or title missing from a list as a wrong option, so an omission can make a wrong option right. `role` (required: `top`, `jungle`, `mid`, `bot`, `support`) is the role of the player's best-known stretch, filled in from general knowledge on 2026-10-24 and unverified like the rest; players known in two roles (Perkz, CoreJJ, Xiaohu, Rekkles, Zven) are excluded from the role question.
- **Player questions** (`ask`, `subject: text`) are made from `data/players.json`; they need no lists, only `label` and `question`, optionally `exclude`, and like pick questions show no values. Kinds: `playerByTeam` (`{team}`: a player who played there vs players who did not), `teamByPlayer` (`{player}`: one of their teams vs teams they never played for), `playerByNickname` (`{nickname}`), `playerByRole` (`{role}`, written as "top laner", "jungler", "mid laner", "bot laner", "support"), `playerByRegion` (`{region}`: a player of that region; a wrong option is from another region **and never played for any team that a player of that region played for**, because e.g. Viper (Korea) made his name in China too), and `playerWithTitle` / `playerWithoutTitle` with `event: "Worlds" | "MSI"` (has won it vs has never won it; `event` is required for these two and rejected elsewhere).
- **Memorable moments** (`subcategory: "moments"`, esports pick questions, one slot a day): each moment is asked in the format that fits it (who: player names; which team: team names, which show logos when all four have one; which champion: champion icons; which year: years as text). Every fact was checked on Wikipedia, Leaguepedia or a sourced esports article on 2026-10-24. **A wrong option must have nothing to do with the moment**: no other player or team from that series, and for champion questions the wrong options are champions **released after the moment**, so none of them can have been played in that game. Text questions must start with "Which" (a test checks the wording).
- **Esports skin lines** (`skinLine: "esports"`, `subject: champion`, `{line}` placeholder, `buildSkinLineRound`): `pipeline/esportsSkins.ts` reads each champion's esports lines from the start of Data Dragon's skin names (team prefixes such as SSG, iG, DRX, and the yearly "Worlds 2019" skin) into the optional `esportsSkinLines` champion field. The answer has a skin in the named line, the wrong options have none. **SKT T1 and T1 are one line, "T1 or SKT T1"**, so a champion with an SKT T1 skin is never offered as having no T1 skin. A new Worlds winner's skin prefix must be added to `TEAM_PREFIXES`, or that line is missing (not wrong). The refresh fails if fewer than 40 champions have a line.
- **Logo question** (`logo: "team"`, `subject: text`, `buildLogoRound`): the round shows one team's downloaded logo above the question (`Round.clue: "teamLogo"`, `clueImageUrl`) and offers that team and three others as plain names. **A round with a clue never shows option images** (`roundSymbols`), or the cards would answer it. Its `teams` list is curated by hand: well-known teams only, one logo per organisation (no T1 next to SK Telecom T1, no Damwon next to Dplus KIA, one Samsung team), and no near-black logos that vanish on the dark background; a test checks each has an entry in `data/esportsImages.json`. Check a logo by eye before adding a team.
- **Region and group crests** (`src/game/textSymbols.ts`): text options named exactly like a region or group (Demacia, Shadow Isles, The Black Rose, House Medarda...) show the crest hotlinked from the LoL Wiki image host (user-approved third-party source). A round shows crests only if **all four** options have one, otherwise the plain cards would hint at the answer. Never map a place inside a nation to that nation's crest (it would reveal "which of these places is in Demacia?"). To add a symbol, add the option name and the wiki file name (`<Name> Crest icon.png`) to `SYMBOL_FILES`.
- **Esports images** (`data/esportsImages.json`, validated by `src/data/esportsImages.ts`): maps `teams`, `leagues` and `players` to file names on Leaguepedia (user-approved source). `npm run images:download` (`pipeline/downloadEsportsImages.ts`, shells out to curl because Fandom blocks Node's HTTP client) saves each as a 160px WebP in `public/images/esports/<kind>/<slug>.webp`, which is committed and served by the app; nothing is hotlinked at runtime. Teams are logos (`<Team>logo square.png`); players are the player page's main photo, resolved once and **not hand-checked** (a few show an old in-game name or an old team). A new team or player needs an entry plus a download run to get an image, and logos are not refreshed automatically after a rebrand. The all-or-nothing rule applies, and a round never mixes logos and photos. Photos are not shown for `playerByTeam`, because the jersey would answer it (`QUESTIONS_WITHOUT_PHOTOS`). A test fails if an entry has no downloaded file.
- **Questions about a given year** (`byYear` list, `subject: text`, `{year}` placeholder, `buildYearRound`) carry their own data: one `{ year, answer }` per year, written in `data/questions/esports.json`. A round names a random year, the answer is that year's entry and the wrong options are answers of other years (so at least 4 different answers, and each year once; an answer may repeat across years). Used for Worlds and MSI winners, Worlds runners-up, Worlds Finals MVPs (2014 on: sources disagree before that) and Worlds final cities. **One name per organisation within a list**, or a wrong option could be argued to be the same team: T1 for SK Telecom T1, Royal Club for Star Horn Royal Club; otherwise era names (Samsung White, Damwon Gaming, DWG KIA). Checked against the Wikipedia Worlds results table and finals pages. Like the other Worlds facts they go stale: **after every Worlds final and MSI, add the new year to each list** (MSI 2020 was cancelled).
- **Snapshots:** each data file holds its own snapshot in effect plus any upcoming one; a day uses the snapshot of each file in effect on that day. New or changed data becomes a snapshot with `effectiveFrom` = next UTC day, so a day's puzzle never changes once that day has started. The client picks the newest snapshot with `effectiveFrom <= today`. Never edit a snapshot that is already in effect. "Changed" ignores key order (Zod reorders keys on parse), and a snapshot identical to the one before it is dropped, so unchanged data never adds a copy.
- **Date handling:** the "day" is defined in **UTC**. Never use local time to pick the puzzle.
- **Fair, escalating rounds:** all 4 champions in a round have distinct values. The relative gap between first and second place must fall in the round's band from `pipeline/generate/config.ts`; bands narrow each round so later rounds are harder. Win rate / pick rate comparisons (Phase 5) should stay within the same role and patch.
- **Data sources:** Data Dragon (official) and the LoL Wiki: champion data (release dates), item data and gold value table (Lua modules, parsed by `luaTable.ts`), each champion's "Patch history" page and each ability's data template (both via a few batched API calls, `leagueWikiPages.ts`). Each lives in one file under `pipeline/sources/`. A stat may return `undefined` for an entity (e.g. not on the wiki yet); validation requires 95% coverage per stat (a stat can lower that) and at least 8 values.
- **Champions, items and abilities:** every stat has a `subject`. A round compares four champions, four items or four abilities, never a mix, and nothing appears twice in a day. Item pool: completed legendary items and boots sold on Summoner's Rift (`items/selectItems.ts`). Item gold efficiency counts the item's stats only (wiki gold values), not passives, and is left out for an item with a stat of unknown value instead of guessing. "Patch changes per year" counts patch-history entries, which include bug fixes and hotfixes, so its question says "patch changes", not "balance changes". "Per year" stats (`pipeline/stats/perYear.ts`) divide by the champion's age measured up to the **newest champion's release date in the data, never today**: a clock would change every value daily and create a data snapshot daily. Champions younger than a year count as one year old.
- **Abilities** (`abilities.json`, ids like `AhriQ`, shown as "Ahri Q · Orb of Deception" with Data Dragon's spell icon): the numbers come from each ability's wiki data template (`Template:Data <Champion>/<Q|W|E|R>`), never from Data Dragon, whose spell numbers are stale. Every value is **at max rank** (rank 5, ultimates rank 3, Jayce/Udyr style champions their own top rank) and every ability question says so. Only values that cannot be argued are kept: damage and ratios only for an ability with exactly one champion damage line (minion, monster and reduced-damage lines are ignored; per-tick, total-plus-per-hit, minimum/maximum and "bonus" lines leave the ability out), and any ratio part that is a formula (e.g. `% per 100 AP`) drops the whole line; cooldown is left out for abilities with charges (`recharge`); mana cost only when the cost is mana alone. Damage and cooldown are split into basic abilities and ultimates; AP, bonus AD and total AD ratios are separate stats because they do not compare. An ability is left out when the wiki's ability name is not Data Dragon's name for that slot (or one of its forms), so an icon never shows another ability's numbers. There is no health-ratio stat: only one damage line scales with the champion's own health.
- **Endless mode** (`?mode=endless[&seed=...]`, `src/game/endless.ts`, `EndlessScreen`) is a testing tool that only exists in development builds (`npm run dev`; in production `?mode=endless` shows the normal game and the code is not in the bundle, gated by `import.meta.env.DEV`). It gives random questions, uniform over stats, an optional category (the question list then shows only that category), forced question/difficulty, and a coverage table grouped by category. It is seeded, saves nothing and never touches the streak. Keep it working when adding stats; its tests check that every stat and difficulty appears, and its Playwright tests run against the dev server.
- **Generator changes move old puzzles:** the puzzle is generated from date + data + stat list + generator code. Adding stats or changing the generator changes the puzzle for every date, including today and the archive. Saved answers that no longer fit are dropped automatically.
- **Stat provenance:** each stat definition carries its `source`, published in its data file. Stat definitions (label, format) and questions are data too: the client has no stat-specific code.
- **No official win-rate API exists** (popularity stats are parked, see plan Phase 5b). Riot does not expose aggregate champion win/pick rate. Whatever source is used must be isolated behind the `pipeline/sources` interface so it can be swapped (see the plan, Risks).
- **Ads only on the game page** (owner, 2026-11-03): `play.html` is the only page that may show ads (`src/ui/AdSlot.tsx`, below the game and the support link; never in the endless mode). The start page and the info pages never load ad code: an ESLint rule forbids importing `src/ads` or `AdSlot` from `src/pages`, and `e2e/ads.spec.ts` checks that those pages never request Google's ad script. Ads are off unless a build sets `VITE_ADS_ENABLED=true` and `VITE_AD_SLOT_ID`, and load only after consent (IAB TCF) where it is required. Keep ad slots away from the answer cards and the Next button. Do not put the AdSense script in any page's HTML: it would load on every page (and with Auto ads, place ads there) before consent.
- **Riot legal:** include the required "not endorsed by Riot Games" disclaimer in the footer. Do not host Riot assets beyond what Data Dragon / Community Dragon terms allow; hotlink or fetch via CI per their terms.

## Maintainability & Clean Code

These are requirements, not suggestions. Apply them to every change.

**Structure**

- Keep **game logic pure**: functions take data and return data. No DOM, network, clock, or randomness inside them (inject those as parameters). This is what makes it testable.
- **Separate concerns by layer:** `pipeline` (produces data) -> `data` (loads/validates) -> `game` (rules) -> `ui` (renders). Dependencies only point in that direction. `ui` must not import from `pipeline`.
- One module = one responsibility. If a file needs "and" to describe it, split it. Aim for files under ~200 lines and functions under ~30.
- **Adding a new stat must be one new file** in `pipeline/stats/` plus registration in one list. If it requires touching the UI or generator, the abstraction is wrong, fix the abstraction.

**Code style**

- TypeScript `strict`. No `any`; use `unknown` and narrow. No non-null `!` assertions without a comment explaining why.
- Names describe intent (`pickHighestChampion`, not `process`). No abbreviations except domain-standard ones (`wr` is not one, write `winRate`).
- Prefer small pure functions, early returns, and immutable data. Avoid deep nesting (max 3 levels).
- No magic numbers or strings: put them in named constants or config (e.g. `MIN_STAT_GAP`, `ROUNDS_PER_DAY`).
- Don't duplicate. Third repetition means extract; but don't abstract on the first use.
- Comments explain **why**, not what. Delete commented-out code. No TODOs without an issue or plan reference.

**Data & errors**

- Validate all external data at the boundary (Zod or equivalent). Everything past the boundary is typed and trusted.
- The pipeline must **fail loudly**: if a source returns bad/partial data, the CI run fails and the previous good data stays live. Never publish a puzzle built from invalid data.
- The client must degrade gracefully: if today's puzzle file is missing, show a clear message (or fall back to the latest available puzzle), never a blank page.

**Testing**

- Every function in `src/game` (including the generator) and `pipeline` has unit tests, including edge cases (ties, missing stat, patch change, date boundary at UTC midnight).
- Add a regression test with every bug fix.
- Generator has a property-style test: for N seeds, every produced round is valid (4 distinct champions, unique max, gap respected).
- Don't mock what you own. Mock only network and clock.

**Dependencies**

- Be sceptical of new dependencies. Prefer the platform and the standard library. Pin versions; justify each addition in the PR/commit message.

**Workflow**

- Small, focused commits with imperative messages ("Add skin count stat"). One concern per commit.
- Keep `IMPLEMENTATION_PLAN.md` current: tick off tasks as done, record decisions that change the plan.
- Update this file when a convention changes. Stale docs are bugs.
- Before finishing a task: typecheck, lint, tests pass; no unused code or exports left behind.

## Working Agreement for Claude

- Check `IMPLEMENTATION_PLAN.md` for the current phase before starting; don't build ahead of it without asking.
- Ask before adding a data source that scrapes a third-party site (ToS / legal risk).
- Prefer the smallest change that solves the problem; don't refactor unrelated code in the same change.
- When unsure about a game-design choice (scoring, difficulty, stat list), propose options rather than silently picking one.
